# 测试方案与测试点

## 目标

验证现有接口在隔离 SQLite 数据库中的可用 CRUD 行为、输入验证、错误码、分页和状态一致性；对代码中可能导致 500 或数据污染的路径进行可复现检查。

## 环境与隔离

- 使用 pytest + FastAPI TestClient。
- 每个测试函数创建一个独立临时文件 SQLite 数据库，并通过 `app.dependency_overrides[get_db]` 替换业务依赖。
- 使用 `check_same_thread=False` 以适配 TestClient 请求线程；不修改业务数据库配置。
- 每个测试结束清理依赖覆盖并释放引擎；正式 `todo.db` 不被测试写入。

## 覆盖点

| 类别 | 测试内容 |
|---|---|
| 基础接口 | 根端点、空列表、每测试独立数据库 |
| 创建/读取 | 默认值、完整字段、创建后按 ID 查询、缺失/空值/结构类型错误 |
| Pydantic 行为 | 整数传入字符串字段的实际强制转换 |
| 路径异常 | 非整数 ID 422、不存在 ID 404 |
| 列表 | skip/limit 切片、limit=0、负 limit 的实际行为 |
| 更新 | 部分更新、空对象不变、可选字段显式 null、结构类型错误、不存在 ID、显式 title null 缺陷复现 |
| 删除/一致性 | 删除成功消息、删除后查询 404、删除不存在 ID 404 |

## 判定原则

- 以源码明确的 Pydantic/HTTP 行为作为可验证契约。
- 对 README 未规定的业务规则（例如标题是否禁止空字符串、分页参数是否必须非负）记录实际行为，并分类为“待确认”，不直接断言为确认缺陷。
- 若输入模型接受请求但服务端产生 500，或接口状态与响应模型/数据库状态冲突，则作为缺陷候选；最终分类必须引用实际测试证据。
