# 实验二 测试用例与条件/判定覆盖矩阵（DeepSeek V4 Pro + Skills 组）

> 被测方法：`com.example.lab2.Calculator#Example(int x, int y, int z)`
> 覆盖标准：语句覆盖 / 判定覆盖 / 条件覆盖 / 条件-判定覆盖
> 约定：`T`=真、`F`=假、`NE`=未求值（Not Evaluated，因短路未执行）

## 1. 被测代码与控制流

```java
public int Example(int x, int y, int z){
    int result = 0;                          // S1
    if(x >= 3 && y == 0){                    // D1 = C1 && C2
        result = z + x;                      // S2  (D1 = true)
    }                                        // (D1 = false 时无 else，落入下一条 if)
    if(z <= 5 || x < z){                     // D2 = C3 || C4
        result = result + x;                 // S3  (D2 = true)
    } else {
        result = result + y;                 // S4  (D2 = false)
    }
    return result;                           // S5
}
```

## 2. 覆盖要素清单

| 类别 | 要素 | 表达式/语句 |
| --- | --- | --- |
| 可执行语句 | S1 | `int result = 0;` |
| 可执行语句 | S2 | `result = z + x;`（D1 真分支） |
| 可执行语句 | S3 | `result = result + x;`（D2 真分支） |
| 可执行语句 | S4 | `result = result + y;`（D2 假分支/else） |
| 可执行语句 | S5 | `return result;` |
| 基本条件 | C1 | `x >= 3` |
| 基本条件 | C2 | `y == 0` |
| 基本条件 | C3 | `z <= 5` |
| 基本条件 | C4 | `x < z` |
| 复合判定 | D1 | `x >= 3 && y == 0`（C1 && C2） |
| 复合判定 | D2 | `z <= 5 || x < z`（C3 \|\| C4） |
| 分支 | B1~B4 | D1 真/假、D2 真/假 |

## 3. 短路求值规则

- `&&`：左操作数为 `F` 时，右操作数不再求值 → 右操作数记为 `NE`。
- `||`：左操作数为 `T` 时，右操作数不再求值 → 右操作数记为 `NE`。
- `NE` 的条件不产生真/假取值，**不计入条件覆盖**（不能把未执行的条件虚报为已覆盖）。
- 因此 C2 只有在 C1=T 时才可能被求值；C4 只有在 C3=F 时才可能被求值。

## 4. 测试用例

| 用例ID | 输入 (x,y,z) | 期望输出 | C1 x>=3 | C2 y==0 | D1 (&&) | C3 z<=5 | C4 x<z | D2 (\|\|) | 覆盖目的 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| TC01 | (3, 0, 5) | 11 | T | T | **T** | T | NE | **T** | D1 真分支执行 S2；`\|\|` 短路（C3=T 故 C4 不求值）；D2 真分支执行 S3 |
| TC02 | (2, 1, 7) | 2 | F | NE | **F** | F | T | **T** | `&&` 短路（C1=F 故 C2 不求值）；C4=T；D2 真分支执行 S3 |
| TC03 | (5, 1, 3) | 5 | T | F | **F** | T | NE | **T** | C2=F 使 D1 为假（C1=T 时 C2 被求值）；`\|\|` 短路；补充组合路径 |
| TC04 | (8, 2, 6) | 2 | T | F | **F** | F | F | **F** | C4=F；D2 为假进入 else 执行 S4 |

### 期望输出推导（人工按代码语义逐句追踪，作为断言 oracle）

- TC01：result=0 → D1=T → result=5+3=8 → D2=T → result=8+3=**11**。
- TC02：result=0 → D1=F（跳过）→ D2=T → result=0+2=**2**。
- TC03：result=0 → D1=F（跳过）→ D2=T → result=0+5=**5**。
- TC04：result=0 → D1=F（跳过）→ D2=F → else result=0+2=**2**。

## 5. 覆盖标准 → 用例映射与满足依据

| 覆盖标准 | 采用用例 | 用例数 | 满足依据 |
| --- | --- | --- | --- |
| 语句覆盖 | TC01, TC04 | 2 | S1、S5 被所有用例执行；S2 由 TC01（D1=T）执行；S3 由 TC01（D2=T）执行；S4 由 TC04（D2=F）执行。5 条语句全部至少执行一次。 |
| 判定覆盖 | TC01, TC04 | 2 | D1=T（TC01）、D1=F（TC04）；D2=T（TC01）、D2=F（TC04）。两个复合判定均取到真、假。 |
| 条件覆盖 | TC01, TC02, TC04 | 3 | C1：T（TC01）/F（TC02）；C2：T（TC01）/F（TC04）；C3：T（TC01）/F（TC02）；C4：T（TC02）/F（TC04）。四个基本条件均取到真、假（NE 不计入）。 |
| 条件/判定覆盖 | TC01, TC02, TC04 | 3 | 上述条件覆盖 + 判定覆盖同时成立（D1=T/D1=F、D2=T/D2=F 均已满足）。 |

> 说明：本组完整测试套件含 4 条用例（TC01~TC04），全部四种覆盖标准均被满足。
> TC03 单独看并非四种标准的最小集所必需，它用于额外验证「C1=T 且 C2=F 使 D1 为假」与「`||` 短路」的组合路径，增强对 `&&` 第二操作数为假的显式覆盖，避免仅靠隐式推导。

## 6. 条件覆盖判定矩阵（T/F/NE 汇总）

| 用例 | C1 | C2 | C3 | C4 | D1 | D2 |
| --- | --- | --- | --- | --- | --- | --- |
| TC01 | T | T | T | NE | T | T |
| TC02 | F | NE | F | T | F | T |
| TC03 | T | F | T | NE | F | T |
| TC04 | T | F | F | F | F | F |

- C1：{T, F} ✓；C2：{T, F}（另 NE）✓；C3：{T, F} ✓；C4：{T, F}（另 NE）✓
